PART 1 - publisher: `publish_frames(repo_root, *, git_binary=None, branch="main", remote="origin", max_attempts=3, pull_fn=None, frames_dir="data/market_motion") -> dict` returning {"status": "published"|"nothing_to_publish"|"failed", "published": [relative paths], "reason": str|None, "commit": sha|None}. Algorithm (git PLUMBING only, never touching the user's index, HEAD, current branch or working tree except the reconcile step):
 a. `git fetch <remote> <branch>`. List frame files on disk under <frames_dir>/snapshots/** (skip dot-temp files, only *.json whose content passes market_motion.validate_frame via a strict per-file load; invalid/corrupt files are skipped and reported, never published). Compute the set NOT present in `<remote>/<branch>` (`git ls-tree -r --name-only <remote>/<branch> -- <frames_dir>`). A path that exists remotely is never overwritten even if bytes differ (report it as "diverged", skip).
 b. If none: return nothing_to_publish.
 c. Build the commit WITHOUT touching the real index: create a temp index file (env GIT_INDEX_FILE=<tmp>), `git read-tree <remote>/<branch>`, for each file `git hash-object -w <path>` then `git update-index --add --cacheinfo 100644,<blob>,<relpath>`, `git write-tree`, `git commit-tree <tree> -p <remote>/<branch> -m "<message>"` (message: `chore: market-motion frames (N) <first..last session date>`; author/committer from `git config user.name/user.email`, falling back to env GIT_AUTHOR_*/GIT_COMMITTER_* set to "market-motion" / "market-motion@localhost" when unset). NEVER pass --allow-empty; NEVER force.
 d. `git push <remote> <commit>:refs/heads/<branch>`. If rejected as non-fast-forward, re-fetch and rebuild from the new tip, at most max_attempts times. Any other failure (auth, network) => status failed with the git stderr trimmed, no retry loop beyond max_attempts.
 e. Reconcile so the local repo does not end up with untracked files that block the next pull: for each published file whose local bytes are IDENTICAL to the pushed blob (compare `git hash-object` to the blob), read its bytes into memory, delete the local copy, then call `pull_fn()` (a callable returning (ok: bool, output: str); default: a fast-forward-only `git pull --ff-only <remote> <branch>` run in repo_root). After the pull, every published file must exist locally with identical bytes; if the pull failed, raised, or any file is missing/different, REWRITE the file from the saved bytes (atomic temp+replace) so NO frame is ever lost, and still report the push as published with a note "local sync pending" (the remote already has it; the next Sync pull will reconcile). Files whose local bytes differ from the pushed blob are never deleted.
 f. Only paths under frames_dir may ever be published; assert this. Never read, list or reference a directory named `position`.
Everything soft-fails into the result dict; the function must never raise.
