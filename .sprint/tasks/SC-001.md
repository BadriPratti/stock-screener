HARD constraint (from the plan): this task must NOT change signal_engine.py's live weights, the buy threshold, or
anything the running dashboard/scanner shows a real user. This is pure backtest-tooling infrastructure.

FILES YOU MAY TOUCH: new files only under scripts/ and/or src/backtesting/ (create src/backtesting/ if it doesn't
exist - check first, it may not), plus scripts/walk_forward_backtest.py and scripts/component_correlation_analysis.py
for the MINIMAL wiring needed to opt into frozen-input mode (do not otherwise restructure either file - both are
real, working tools other people run manually; preserve their existing CLI/behavior when frozen mode isn't
requested). New tests under tests/.

CONTEXT (verified by the lead and a peer's independent read - both agree): `run_walk_forward()` in
scripts/walk_forward_backtest.py currently fetches the stock universe, all price histories, and SPY history FRESH
from yfinance on every single run (lines ~183-197), and never persists what it fetched. `component_correlation_analysis.py`
has the same problem plus no fixed random seed for its pool sample. This means two "identical" runs today are
NOT reproducible - the underlying data itself silently changes between runs (yfinance revises adjusted prices,
the universe list can change, etc.), which makes any before/after comparison of a scoring change unsound.

GOAL: build a manifest + frozen-input system so a backtest run's exact inputs can be captured once and replayed
byte-for-byte identically, any number of times, by anyone, indefinitely (not just "for now until yfinance changes
something").

REQUIREMENTS
1. A manifest schema (JSON) capturing at minimum: a unique id, created-at timestamp, git commit hash of the repo
   at creation time (best-effort if git unavailable), the exact universe ticker list used, the random seed, all
   CLI parameters (universe_size, lookback_months, step_days, top_n, max_hold_days, etc.), and content
   hashes (e.g. sha256) of every frozen price-history file so tampering/corruption is detectable.
2. A frozen-input store: when a run is invoked in "capture" mode, save the exact universe sample, every fetched
   ticker's price history (as actually used - already-sliced to whatever `period='2y'` returns, not re-fetchable
   later), and the SPY history, to durable local files (pick a sane format - parquet if pandas/pyarrow is already
   a dependency, else a stable CSV/JSON encoding; check requirements.txt / venv for what's already available
   rather than adding a new dependency if avoidable) under something like data/backtest_manifests/<manifest_id>/.
   Write the manifest JSON alongside it.
3. A "replay" mode: given a manifest id, `run_walk_forward` (and ideally `component_correlation_analysis.py`'s
   pool-building step too, though that one is a stretch goal if time allows - prioritize walk_forward_backtest.py)
   loads the frozen universe/histories/SPY data from the manifest's store INSTEAD of calling yfinance, and
   produces trades/metrics using that data. No network calls happen in replay mode - verify this concretely (e.g.
   assert no fetcher is invoked, or run with network mocked/blocked in a test).
4. CLI additions: e.g. `--capture-manifest <path-or-auto-id>` (fetch live, save everything, then run) and
   `--replay-manifest <manifest_id>` (skip all fetching, load frozen data, run). Keep the existing default
   behavior (fetch live, no manifest saved) working exactly as it does today when neither flag is passed - don't
   force manifest capture on everyone.
5. Acceptance criterion from the plan, verify it directly: running the SAME manifest through `--replay-manifest`
   twice produces byte-identical trades/metrics/component_correlations JSON output both times. A run using a
   DIFFERENT manifest (or live-fetch mode) is allowed to differ - the point is determinism GIVEN the same frozen
   inputs, not that all runs agree with each other.
6. Do not silently swallow a missing/corrupt manifest file or a hash mismatch - fail loudly with a clear error,
   never fall back to fetching live data when replay mode was explicitly requested.

TESTS: unit tests for manifest schema validation, hash verification (tamper with one byte of a frozen file,
confirm replay refuses to run), capture-then-replay determinism (two replay runs of the same manifest produce
identical output - this is the core acceptance test, make it real and strong, not just "doesn't crash"), replay
mode makes zero network calls (mock/patch the fetcher and assert it's never called), and that default (neither
flag) behavior is unchanged from before your change (existing tests for walk_forward_backtest.py, if any exist,
must still pass - check first). Use small synthetic fixtures for the fast tests (a handful of fake tickers/bars),
not real multi-year yfinance data, so the test suite stays fast; one slower/optional integration test using real
data is fine if clearly marked and skippable.
