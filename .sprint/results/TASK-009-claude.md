# TASK-009 result (Claude)

Accessibility (ARIA, keyboard nav, focus states) and responsive-layout pass, additive only — no data-fetching/rendering logic changed, no desktop-width visual change except focus rings (keyboard-only) and the new narrow-width breakpoint.

## Checklist against the 8 scope items

1. **Landmarks & headings** — done. `templates/dashboard.html`: `<nav class="sidebar">` got `aria-label="Primary"`; each `.nav-group` got `role="group" aria-label="Monitor|Analyze|Run"` matching its visible `.nav-group-label` text. `<header class="topbar">` was left without an explicit `role="banner"` — per the HTML spec a `<header>` only gets the implicit banner role when it is NOT a descendant of `main`/`article`/`aside`/`section`/`nav`, and this one lives inside `<main class="main">`, so it correctly has no banner role already; adding one explicitly would be wrong.
2. **Nav active state** — done. `static/js/core/router.js`'s `route()` now sets/removes `aria-current="page"` in the same `forEach` that already toggles `.active`, keyed off the same `isActive` boolean (no duplicated condition logic).
3. **Focus states** — done. Added a `:focus-visible` rule in `static/css/dashboard.css` for `a`, `button`, `input`, `select`, and `[tabindex]`, using the existing `--focus-ring` token. Deliberately did NOT also set `border-radius` in that rule — elements keep their own radius and the box-shadow follows it automatically; forcing a fixed radius there would have visibly clipped larger-radius elements like `.chart-toggle-btn` (8px) on focus.
4. **Keyboard-operable controls** — audited via grep for `onclick=` and manual click-handler wiring across `static/js/`. Found exactly one real gap: `static/js/views/backtests.js`'s sortable trade-table `<th data-key>` headers had a `click`-only listener with no keyboard path. Fixed: added `role="button" tabindex="0" aria-sort="none"` to each header, extracted the sort logic into a shared `applySort(th)` function, wired both `click` and `keydown` (Enter/Space, with `preventDefault` on Space to stop page scroll), and now update every header's `aria-sort` after each sort (active column gets `ascending`/`descending`, others reset to `none`). `toggleReasons` (`core/ui-helpers.js`, wired via `onclick="toggleReasons(this)"` in `market.js`) needed no fix — it's already a real `<button class="expand-btn">`, natively keyboard-operable. `components/data-table.js`'s `dataTableHTML` generates `aria-sort`-ready sortable `<th>` markup but has zero consumers anywhere in the app yet (grep confirms no view imports it) — it's forward-looking/inert, so there's no live click-vs-keyboard gap to fix there; only added `scope="col"` (item 6) since that's correct regardless of adoption.
5. **aria-live regions** — done, narrower than the task's own suggestion. Added `role="status" aria-live="polite"` to the job status pill in `static/js/components/job-panel.js` (`jobPanelHTML`) — this changes rarely (idle→running→success/error) and is exactly what's worth announcing. Deliberately did NOT add `aria-live` to the adjacent `.job-output` log div, despite the task prompt suggesting "(and/or output area)": that div is overwritten with the full accumulated log text on every ~1.5s poll tick while a job runs (`core/jobs.js`'s `watchJob`), so making it live would re-announce the entire growing log to screen reader users every 1.5 seconds — a real regression, not an improvement. Also added `role="status" aria-live="polite"` to the `#toast` element in `templates/dashboard.html` (`showToast`, `core/ui-helpers.js`), so sync/error toasts get announced.
6. **Table accessibility** — done. `dataTableHTML`'s `aria-sort` mapping was already correct (`asc`→`ascending`, `desc`→`descending`, unsorted columns get none). Added `<th scope="col">` to every hand-rolled table: `static/js/views/market.js` (Buy Signals, Sell Signals tables), `static/js/core/ui-helpers.js` (`renderTop20Table`), `static/js/views/backtests.js` (trades table, alongside the sort-keyboard fix in item 4), and `static/js/components/data-table.js`'s generated markup. `positions.js`/`shortlist.js`/`run.js`/`scan.js` contain no `<table>` elements — nothing to do there.
7. **Color contrast / non-color signal** — audited, no changes made. The dark palette's status colors (`--green #22c55e`, `--red #ef4444`, `--yellow #eab308`, `--blue #3b82f6`) against the app's dark surfaces (`--surface #1a1d27`, `--bg #0f1117`) all clear WCAG AA for normal text by a comfortable margin (all are mid-to-high luminance colors on a very dark ground). Every color-coded status indicator found (`.badge`, `.status-pill`, `.momentum-badge`, `.trade-link`, `.regime-badge`) already pairs color with a text label (e.g. "GOOD"/"POOR", "BUY"/"SELL", "HOT"/"STABLE", the status pill's own status word) — none rely on color alone. No color-only indicator was found that needed a cheap icon/text fix, so nothing was changed here; a full contrast-ratio audit tool wasn't available in this sandbox, so this is a reasoned read of the token values rather than a machine-verified one.
8. **Responsive pass (~400px)** — done, deliberately minimal per the task's own guidance that this is a defensive minimum for a native-window desktop app (`mac_app/main.py` opens at `min_size=(900, 600)`), not a primary target. Added one `@media (max-width: 760px)` block in `dashboard.css`: the sidebar drops its `position: sticky`/fixed 220px width and becomes a wrapping horizontal bar (`flex-direction: row; flex-wrap: wrap`) above the content, group labels and nav-item subtitles hide (redundant at that size), nav items get simple rounded hover targets instead of the left-border active indicator, and `.topbar`/`.content` padding shrinks. Existing grid layouts (`.grid-3`, `.stats-row`, `.shortlist-grid`, all `repeat(auto-fit/auto-fill, minmax(...))`) already collapse to a single column at narrow widths with no changes needed. All tables were already confirmed wrapped in `overflow-x:auto` containers (see item 6's files) so no page-level horizontal scroll risk from data tables.
